# Jira Task - 快速開始指南

5 分鐘學會使用 `/do-do-jira-task` 自動完成 Jira 任務實作！

## 🚀 最簡單的使用方式

```bash
/do-do-jira-task EK-920
```

就這麼簡單！

## 📝 完整流程示例

### 情境：要實作一個新功能

**你的 Jira Issue:**
- **EK-920**: 新增使用者個人資料編輯功能
- **描述**: 使用者可以編輯暱稱、頭像、個人簡介

**Step 1: 執行 skill**
```bash
/do-do-jira-task EK-920
```

**Step 2: 回答我的問題**

我會詢問：
```
❓ 需要確認以下事項：

1. 編輯頁面的 UI 設計圖在哪裡？
2. 上傳頭像的 API endpoint 是什麼？
3. 暱稱長度有限制嗎？
4. 儲存失敗時要顯示什麼錯誤訊息？

📦 需要的資源：
- [ ] 編輯頁面設計圖
- [ ] 頭像上傳 API 文檔
- [ ] 預設頭像圖片
```

你只需要回答：
```
1. 設計圖: https://figma.com/...
2. API: POST /api/user/profile
3. 暱稱 2-20 字
4. 顯示 Toast: "儲存失敗，請稍後再試"
```

**Step 3: 確認 TODO 清單**

我會創建：
```
✅ 已創建 6 個任務：

1. [ ] 創建 ProfileEditScreen Compose UI
2. [ ] 實作 ProfileEditViewModel
3. [ ] 添加頭像上傳功能
4. [ ] 實作表單驗證邏輯
5. [ ] 處理儲存和錯誤情況
6. [ ] 測試完整流程
```

**Step 4: 自動執行**

我會依序完成所有任務，你只需要等待：
```
▶️  [1/6] 正在創建 ProfileEditScreen Compose UI
✅ 已完成

▶️  [2/6] 正在實作 ProfileEditViewModel
✅ 已完成

... (繼續)

🎉 所有任務已完成！
```

**Step 5: 測試與提交**

完成後你可以：
```bash
# 測試功能
# 然後創建 PR
/jira-pr EK-920
```

## ⚙️ 快速設定

### 確認 Jira 連接
```bash
# 確保 .claude/settings.local.json 有以下設定：
{
  "mcpServers": {
    "jira": {
      "command": "...",
      "env": {
        "JIRA_EMAIL": "your-email@example.com",
        "JIRA_API_TOKEN": "your-token"
      }
    }
  }
}
```

### 第一次使用
1. 確保在專案根目錄
2. 準備好一個 Jira issue
3. 執行 `/do-do-jira-task <issue-key>`

## 🎯 使用技巧

### 技巧 1: 提供充足資訊

**❌ 不好的 Jira 描述:**
```
新增分享功能
```

**✅ 好的 Jira 描述:**
```
新增社群分享功能

需求：
- 使用者可以分享貼文到 Facebook 和 Twitter
- 分享前顯示預覽
- 分享成功後顯示 Toast 提示

設計圖: [連結]
API 文檔: [連結]
```

### 技巧 2: 準備資源

執行前準備好：
- 📐 設計圖（Figma/Sketch 連結）
- 📄 API 文檔
- 🎨 設計資源（icon、圖片）
- 📝 文案內容

### 技巧 3: 即時溝通

遇到我的提問時：
- ✅ 直接回答問題
- ✅ 提供連結或檔案
- ✅ 不確定時說「我也不確定，你建議呢？」

## 📊 預期時間

| Issue 類型 | 複雜度 | 預期互動次數 | 建議準備時間 |
|-----------|--------|------------|------------|
| 簡單 Bug 修復 | 低 | 0-2 次 | 無需準備 |
| UI 調整 | 中 | 2-4 次 | 準備設計圖 |
| 新功能實作 | 高 | 4-8 次 | 準備完整資源 |
| 架構重構 | 高 | 3-6 次 | 理解現有架構 |

## ❓ 常見問題

### Q1: 我不知道需要什麼資源怎麼辦？

**A:** 沒關係！我會主動告訴你缺少什麼。你只需要在我詢問時提供即可。

### Q2: 執行中可以暫停嗎？

**A:** 可以！隨時告訴我「先暫停」，我會停下來等你的指示。

### Q3: 如果實作方向不對怎麼辦？

**A:** 立即告訴我「這個方向不對」，我會調整策略。

### Q4: 可以只分析不實作嗎？

**A:** 可以！在創建 TODO 清單後告訴我「先不要實作」。

### Q5: 需要我有很強的技術背景嗎？

**A:** 不需要！我會處理技術細節，你只需要：
- 了解業務需求
- 能提供設計資源
- 回答我的問題
